# 02 - Variables and Outputs

**Series:** Terraform Labs  
**Lab:** 02 | **Prereq:** 01-first-resource.md  
**Goal:** Stop hardcoding values. Use variables for flexibility and outputs to surface important info.

---

## 🧠 Concepts

### Input Variables
Variables let you parameterize your configs. Instead of hardcoding `"production"` everywhere, define it once and reuse it.

```hcl
variable "environment" {
  type    = string
  default = "dev"
}
```

Reference it with: `var.environment`

### Output Values
Outputs display values after `terraform apply` — like printing results. Useful for surfacing IPs, URLs, IDs.

```hcl
output "file_path" {
  value = local_file.config.filename
}
```

## 🔬 Lab 1 — Input Variables

### Setup

```bash
mkdir -p ~/terraform-labs/02-variables
cd ~/terraform-labs/02-variables
```

### variables.tf

```bash
nano variables.tf
```

```hcl
variable "environment" {
  type        = string
  description = "Deployment environment"
  default     = "dev"
}

variable "owner" {
  type        = string
  description = "Owner of this infrastructure"
  default     = "ed"
}

variable "message" {
  type        = string
  description = "Message to write to file"
  # No default — will be required at runtime
}
```

### main.tf

```bash
nano main.tf
```

```hcl
terraform {
  required_providers {
    local = {
      source  = "hashicorp/local"
      version = "~> 2.0"
    }
  }
}

resource "local_file" "config" {
  filename = "${path.module}/${var.environment}-config.txt"
  content  = "Owner: ${var.owner}\nEnvironment: ${var.environment}\nMessage: ${var.message}\n"
}
```

### Run it

```bash
terraform init
terraform plan
```

Terraform will prompt you for `message` since it has no default:
```
var.message
  Message to write to file

  Enter a value: Hello from Terraform variables!
```

```bash
terraform apply
cat dev-config.txt
```

## 🔬 Lab 2 — terraform.tfvars

Instead of typing values every time, store them in a file:

```bash
nano terraform.tfvars
```

```hcl
environment = "production"
owner       = "ed"
message     = "This config was generated by Terraform"
```

Now run:

```bash
terraform apply
```

No prompts — Terraform reads from `terraform.tfvars` automatically.

Check that the file created is now called `production-config.txt`.

## 🔬 Lab 3 — Output Values

### outputs.tf

```bash
nano outputs.tf
```

```hcl
output "config_filename" {
  description = "The path of the config file created"
  value       = local_file.config.filename
}

output "environment_info" {
  description = "Environment and owner summary"
  value       = "Environment: ${var.environment} | Owner: ${var.owner}"
}
```

```bash
terraform apply
```

After apply you'll see:
```
Outputs:

config_filename = "./production-config.txt"
environment_info = "Environment: production | Owner: ed"
```

View outputs anytime without re-applying:
```bash
terraform output
terraform output config_filename   # specific output
```

## 🔬 Lab 4 — Variable Types

Variables aren't just strings:

```hcl
variable "port_list" {
  type    = list(number)
  default = [22, 80, 443]
}

variable "tags" {
  type = map(string)
  default = {
    project = "rhce-study"
    owner   = "ed"
    env     = "dev"
  }
}

variable "enable_logging" {
  type    = bool
  default = true
}
```

Reference them:
```hcl
# List — access by index
first_port = var.port_list[0]   # 22

# Map — access by key
project_tag = var.tags["project"]   # "rhce-study"

# Bool
logging = var.enable_logging   # true
```

## 🔬 Lab 5 — Override with -var flag

```bash
# Override one variable at runtime
terraform apply -var="environment=staging"

# Override multiple
terraform apply -var="environment=staging" -var="owner=victor"
```

**Precedence (lowest → highest):**
1. Default values in `variables.tf`
2. `terraform.tfvars`
3. `*.auto.tfvars` files
4. `-var` and `-var-file` flags (highest)

## 🔬 Lab 6 — Sensitive Variables

Mark secrets so Terraform doesn't print them in logs:

```hcl
variable "db_password" {
  type      = string
  sensitive = true
}
```

Outputs can also be sensitive:
```hcl
output "password_reminder" {
  value     = var.db_password
  sensitive = true
}
```

## 📚 Key Takeaways

| Concept | What to Remember |
|---------|-----------------|
| `variable "name" {}` | Declare input variables in `variables.tf` |
| `var.name` | Reference a variable |
| `terraform.tfvars` | Auto-loaded variable values file |
| `output "name" {}` | Declare outputs in `outputs.tf` |
| `terraform output` | View outputs without re-applying |
| `sensitive = true` | Hides value from logs/output |
| `-var="key=val"` | Runtime override (highest precedence) |
