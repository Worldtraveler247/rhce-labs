00
Introduction to Terraform
What Terraform is, how it thinks (Write → Plan → Apply → Destroy), key files, and the declarative model. Understand state, providers, and how Terraform compares desired vs actual infrastructure.
IaC concepts terraform init terraform plan terraform apply terraform destroy .tfstate providers
Beginner
01
Your First Resource (No AWS Needed)
Write your first HCL config using the local provider to create files on disk. Run the full init → plan → apply → modify → destroy cycle. Learn terraform fmt and validate.
HCL syntax local_file resource block terraform fmt terraform validate state file
Beginner
02
Variables and Outputs
Stop hardcoding values. Define input variables with types and defaults. Store values in terraform.tfvars. Surface important results with output values. Understand variable precedence.
variable block var.name terraform.tfvars output block sensitive = true -var flag type constraints
Beginner
03
AWS Provider — Real Cloud Resources
Connect Terraform to AWS. Create an S3 bucket with versioning, then an EC2 instance. Learn data sources to read existing resources. Always destroy when done to avoid charges.
provider "aws" aws_s3_bucket aws_instance data sources aws_ami resource tags free tier
Beginner
— Intermediate —
04
State Management
Understand what the state file does and why local state is dangerous for teams. Set up S3 remote backend with DynamoDB locking. Learn state commands for moving, removing, and importing resources.
terraform.tfstate S3 backend DynamoDB locking terraform state list terraform state mv terraform import
Intermediate
05
Modules — Reusable Infrastructure
Build reusable module directories so you stop copy-pasting configs. Call the same module for dev, staging, and prod. Use the public Terraform Registry for community modules. Pin versions.
module block source = "./path" module outputs registry modules version pinning module composition
Intermediate
06
Workspaces — Dev / Staging / Prod
Manage multiple environments from a single codebase using workspaces. Each workspace gets its own state file. Use terraform.workspace in configs to change behavior per environment.
terraform workspace new terraform workspace select terraform.workspace locals block lookup() env-aware naming
Intermediate
— Advanced —
07
Terraform + Ansible Together
Use Terraform to provision cloud infrastructure, then hand off to Ansible to configure it. Bridge the two tools via terraform output to generate Ansible inventory. The ultimate IaC stack.
terraform output dynamic inventory local-exec provisioner aws_ec2 plugin deploy pipeline provision + configure
Advanced
08
Security — IAM, Secrets, and Best Practices
Write secure Terraform: never hardcode credentials, use least-privilege IAM, encrypt state with KMS, mark sensitive variables, use Secrets Manager, and scan code with tfsec.
no hardcoded creds least privilege IAM sensitive = true KMS encryption Secrets Manager tfsec scanner .gitignore
Advanced
— Expert —
09
CI/CD with GitHub Actions
Automate Terraform with GitHub Actions: run terraform plan on every PR (posts output as a comment), apply automatically on merge to main. Add environment approval gates for production.
GitHub Actions workflow plan on PR apply on merge GitHub Secrets environment gates tfsec in CI -no-color
Expert
10
Full Project — Production VPC
Capstone project: build a complete production-grade AWS environment. Multi-AZ VPC, public/private subnets, Internet Gateway, NAT Gateway, bastion host, app servers, security groups, remote state, and tags. Everything modular.
multi-AZ VPC public/private subnets NAT Gateway bastion host security groups module composition default_tags full production
